01

HTML Fundamentals

The concept

HTML describes what content is. A heading is a heading, a list is a list, a navigation is a navigation. Browsers, search engines, and screen readers all depend on this meaning.

Common beginner mistake

Using <div> and <span> for everything, and picking heading levels by how big they look.

Why it happens

After styling, a div looks identical to a real heading, so the problem is invisible on screen. Generated code is often full of divs too.

The correct approach

Choose the element that matches the meaning: header, nav, main, section, h1 to h6 in order, ul for lists, and alt text on every image. Use one h1 per page.

Example

Takeaway

Pick HTML elements for what the content means, then use CSS for how it looks.

02

CSS Foundations

The concept

CSS chooses elements with selectors and sets their properties: colour, font, spacing, and layout. Every element is also a box made of content, padding, border, and margin. This is the box model.

Common beginner mistake

Typing the same colours and sizes everywhere, and adding !important whenever a style does not apply.

Why it happens

Quick fixes pile up. When two rules disagree, !important feels like the fastest way to make one win.

The correct approach

Style with classes, store repeated values in CSS variables, use a small spacing scale (8, 16, 24, 32px), and add box-sizing: border-box so widths include padding.

Example

Takeaway

Define a value once, reuse it everywhere, and avoid fighting your own CSS.

03

Layout and Responsiveness

The concept

Flexbox arranges items in one row or column. Grid arranges items in rows and columns together. Media queries change the layout when the screen gets wider or narrower.

Common beginner mistake

Fixed pixel widths, absolute positioning, and forgetting the viewport meta tag.

Why it happens

The page looks right on your own screen, so you assume it looks right everywhere.

The correct approach

Design for the phone first. Use max-width instead of width, let Flexbox or Grid place things, and add media queries with min-width for larger screens. Always include the viewport tag in the <head>.

Example

Takeaway

Start small, then add layout as the screen grows. Test at 375px, 768px, and 1200px.

04

Clean Code

The concept

Clean code is code another person, or you in three months, can read and change without a struggle.

Common beginner mistake

Vague class names like box2 or red-text, messy indentation, and leftover unused code.

Why it happens

When rushing, any name that works feels good enough. Generic generated code often uses generic names.

The correct approach

Name things by purpose, indent consistently, group CSS into labelled sections, write comments that explain why, and delete code you do not use.

Example

Takeaway

A good name explains what something is for, not what it looks like today.

05

AI-Assisted Development

The concept

AI is a fast assistant, not a replacement for understanding. You stay responsible for what you publish.

Common beginner mistake

Pasting generated code without reading it, and asking for a whole website in one go.

Why it happens

The output looks polished and confident, so it feels finished even when it is not.

The correct approach

Ask for small pieces. Ask the AI to explain each line. Read it, run it, try to break it by resizing and using the keyboard, and then change something yourself to prove you understand it.

Example

Takeaway

Use AI to learn faster, not to skip learning.

06

Publishing Checklist

The concept

A final set of checks before real people see your site. It catches the small mistakes that make a project look unfinished.

Common beginner mistake

Publishing after testing on only one screen, leaving placeholder text, or shipping broken links.

Why it happens

Deadlines. By the end of a project you stop seeing your own mistakes.

The correct approach

Work through the same short list every time. Tick the boxes below as you go; they reset when you reload the page.
