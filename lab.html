The Lab

Learn by finding what's wrong.

Three short experiences. See a poor design fixed, test your own eye, then read broken code next to a better version.

A. Before & After Studio

Same content, two designs. Read what was wrong, then why the new version works.

Example 1: A landing page

What was wrong

  • Vague words. "Unlock Your Full Potential" could describe any product.
  • Decoration over content. The gradient, glow, and shadows compete with the text.
  • Weak button. It is tiny, low contrast, and says only "Click".
  • Filler cards. "Fast, Smart, Easy" are three boxes that say nothing.
  • Mixed fonts. A serif heading and a sans-serif body with no reason.
  • Poor contrast. Pale grey text on a grey gradient is hard to read.

Why the improved version is better

  • Specific copy tells the visitor exactly what they get.
  • Clear hierarchy. Small label, large heading, short text, one button.
  • Strong contrast. Near-black text on white is easy to read.
  • One action. The solid button is the only thing to click.
  • Consistent type. One heading font, one body font.
  • Calm layout. Left alignment and whitespace guide the eye down the page.

Example 2: Reading text

What was wrong

  • Font size around 11px is too small for body text.
  • A line height of 1.1 packs lines together.
  • Grey on grey fails basic contrast.
  • Justified text creates uneven gaps.

Why the improved version is better

  • About 15 to 18px with a line height near 1.6 suits reading.
  • Near-black on white gives strong contrast.
  • A limited line length keeps your place easy to find.
  • Left alignment keeps word spacing even.

B. Spot the Mistake

Read each example, choose what you think is wrong, then press "Check answer". You can change your answer and check again.

Score: 0 / 4

1. What is wrong with these headings?

Headings describe structure, not size. After an h1 the next level should be an h2. If the text looks too big or small, fix it with CSS, not by changing the heading level.

2. What is the main problem with this text?

Submit your assignment by Friday at 5 pm. (Text colour: #BBBBBB on white.)

Pale grey on white is hard to read, especially on phones in sunlight or for people with low vision. Use a dark colour such as #111111 for important text.

3. What happens to this CSS on a 375px wide phone?

A fixed width of 800px does not adapt to small screens. Use max-width: 100%; and height: auto; so the image can never be wider than its container.

4. What is missing from this image tag?

The alt text is read by screen readers and shown if the image fails to load. For example: <img src="team.jpg" alt="Five students at a whiteboard">. The img tag never needs a closing tag.

C. Code Autopsy

Three real-world patterns. Read the problem, then the improved version, then the reasons.

Case 1: A navigation built from divs

What is wrong

Divs are not links. Keyboard users cannot tab to them, screen readers do not announce them as navigation, you cannot open them in a new tab, and they stop working if JavaScript fails.

Why the improved code is better

A real <a href> inside a <nav> list works with the keyboard, assistive technology, and every browser feature for free. It is also shorter and needs no JavaScript.

Case 2: A button placed with absolute positioning

What is wrong

Those numbers only look right on the one screen the author tested. On a phone the button can overlap text or fall off the page, and because it is removed from the normal flow, other content ignores it.

Why the improved code is better

Flexbox lets the browser place items one after another and wrap onto a new line when space runs out. The gap property keeps consistent space between them, with no magic numbers.

Case 3: Repeated values and !important

What is wrong

The same colour is typed twice, the spacing values (17px, 13px) are random, and !important forces a style to win instead of fixing the real conflict. This gets harder to manage with every new rule.

Why the improved code is better

CSS variables store each value once, so changing the colour means editing one line. A small spacing scale makes the layout consistent, and without !important the rules stay predictable.
